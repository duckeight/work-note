# 다른 컴퓨터의 Codex에 적용할 Notion 작업 기록 설정

이 파일을 받은 Codex는 설명만 하지 말고 아래 설정을 직접 설치·검증한다. 사용자는 폴더 복사나 AGENTS.md 수동 편집 없이 이 파일 하나로 설치를 요청했다. 계정 인증이 필요할 때만 사용자가 로그인하도록 안내한다. 기존 지침은 보존한다.

## 사용자가 승인한 범위

- Codex 프로젝트별 기존 Notion DB 재사용, 새 프로젝트 DB 생성, 채팅별 페이지, 한국 날짜별 짧은 작업 기록, 요청 시 일일 요약을 지속 수행한다.
- 이 컴퓨터의 사용자 수준 Codex 지침에 기록 절차를 설치한다. 기존 AGENTS.md는 교체하지 않고 중복 없는 참조 절만 추가·갱신한다.
- 이 컴퓨터에는 정기 요약 예약을 만들지 않는다. 일일 요약은 별도의 클라우드 실행 한 곳에서 담당한다. 클라우드 예약은 2026-10-28 등록·활성화 및 Notion 읽기·쓰기 검증을 완료했다. 관리 채팅은 https://chatgpt.com/c/6ae1931a-db34-83e8-85a1-23756728238d 이다. 일정은 매일 00:05(Asia/Seoul), 전날 기록 요약이며 첫 예약 실행은 아직 미검증이다. 현재 상태가 필요하면 해당 예약을 조회한다.
- 다른 계정 저장, 공유·권한 변경, 자료 삭제·이동, 과거 대화 전문 수집은 승인하지 않는다.

## 지금 자동으로 수행할 설치

1. 현재 적용 중인 사용자·프로젝트 지침을 읽는다. 실제 Codex 사용자 설정 디렉터리를 확인한다. CODEX_HOME이 지정돼 있으면 해당 경로, 없으면 이 컴퓨터 사용자 홈의 `.codex`를 사용한다. 과거 컴퓨터의 `/Users/nextree_kyj`를 하드코딩하지 않는다.
2. 이 파일의 지속 실행 규칙을 `<Codex 설정 디렉터리>/notion-worklog/WORKFLOW.md`로 저장한다. config.json에는 위 계정·워크스페이스·페이지·DB와 이 컴퓨터에서 확인한 프로젝트 ID 매핑을 저장한다. 기존 파일이 있으면 읽어서 사용자 설정을 보존하고 필요한 부분만 갱신한다. 자격증명을 복사하거나 저장하지 않는다.
3. 사용자 수준 AGENTS.md에 `## Notion 프로젝트·세션 작업 기록` 절을 한 번만 추가·갱신한다. 이 컴퓨터에서 해석되는 WORKFLOW.md/config.json의 실제 절대 경로를 넣고, 새 세션 첫 작업 전 읽기, 의미 있는 작업 후 기록, 응답 전 저장 결과 확인, 계정 제한, 중복 방지를 명시한다. 기존 다른 지침을 제거하지 않는다. 파일 쓰기에 실행 환경의 승인이 필요하면 정식 승인 절차를 사용한다.
4. 현재 제공되는 Notion 도구에서 개인 계정 연결을 고른다. link_id는 다른 컴퓨터에서 가져오지 말고 현재 목록에서 선택한다. get_self 등 연결 정보로 위 이메일과 워크스페이스 ID를 확인하고 기록 홈·기존 DB·전체 요약 페이지를 읽는다. 연결이 없으면 공식 플러그인 연결 절차로 사용자가 인증하도록 안내한다. yjkim@nextree.io로 우회하지 않는다.
5. list_projects 및 현재 채팅 메타데이터로 실제 프로젝트 ID·이름을 확인한다. 위 논리 프로젝트와 명확히 대응하면 새 컴퓨터의 ID를 기존 DB에 매핑한다. 기존 DB 설명의 최초 프로젝트 ID를 덮어쓰지 않는다. 같은 이름의 후보가 여럿이면 그 항목만 사용자에게 확인하고 나머지는 진행한다. 폴더 이름만으로 소속을 추측하지 않는다.
6. 현재 채팅 ID를 CODEX_THREAD_ID 등 확인된 메타데이터에서 얻는다. 기록 홈의 기존 DB 전체에서 같은 세션 ID를 확인하고 기존 페이지가 있으면 재사용한다. 없으면 실제 채팅 소속 DB에 현재 세션 페이지를 만들고 설치 결과를 짧게 기록한다. 설치만을 위해 별도 테스트 페이지를 만들지 않는다.
7. 설치 파일의 정상 저장, AGENTS 절 중복 없음, 정확한 계정·기존 DB 재사용, 현재 세션 기록의 실제 저장을 검증하고 결과 링크를 알려준다. 새 세션 자동 기록은 실제 새 세션을 확인하기 전에는 미검증으로 표시한다.

## 지속 실행 규칙

### 세션과 프로젝트

- 새 세션 첫 요청에 WORKFLOW.md/config.json을 읽고 현재 계정과 워크스페이스를 확인한다. 한 세션에서 확인한 연결·스키마는 재사용한다.
- 실제 프로젝트 메타데이터를 우선하고, 프로젝트 없는 채팅은 미분류로 기록한다. 워크트리는 원래 프로젝트로 묶는다.
- 새 프로젝트는 먼저 기록 홈의 자식 DB·메타데이터와 로컬 매핑을 확인한다. 기존 논리 프로젝트면 DB를 재사용한다. 동일 여부가 모호하면 중복 DB를 만들기 전에 확인한다. 새로운 논리 프로젝트에만 DB를 만들고 확인된 Codex 프로젝트 ID를 설명에 기록한다.
- 새 DB 기본 속성: 이름(title), 세션 ID(rich_text), 시작일(date), 최근 기록일(date), 상태(select: 진행 중·완료·보류). 기존 DB는 fetch한 실제 스키마가 우선이다.
- 세션 ID로 정확히 조회한다. SQL은 바인딩 매개변수·단일 데이터 소스를 사용한다. 제한 시 저장된 뷰와 페이지네이션으로 확인한다. 검색 결과가 없다는 이유만으로 새 페이지를 만들지 않는다.
- 재개·날짜 변경·프로젝트 변경에도 같은 세션은 기존 페이지를 이어 쓴다. 새 채팅·포크는 확인된 새 ID로 구분한다. 불명확한 생성 실패는 결과를 먼저 조회하고 재시도한다.

### 작업 기록

- 날짜는 신뢰할 수 있는 현재 시각의 Asia/Seoul 기준이다. Notion Markdown 명세를 읽고 날짜를 `<date start="YYYY-MM-DD" />`로 표시한 2단계 제목을 사용한다.
- 날짜 안에 `### 작업 기록`, 마지막에 `### 오늘 한 일`을 둔다. 추가 기록은 요약 위에 넣는다.
- 의미 있는 작업을 마칠 때 요청·수행 결과·검증·남은 일을 2~5개 짧은 항목으로 남긴다. 매 도구 호출·전체 대화·코드·비밀은 저장하지 않는다. 확인된 사실과 제안을 구분한다.
- 사용자 메모·체크 상태·다른 날짜는 보존한다. 같은 사실을 중복 누적하지 않는다. 최신 본문을 읽고 최소 범위를 갱신한다.
- 실제 작업을 추가할 때만 최근 기록일을 갱신한다. 완료되지 않은 일은 완료로 표시하지 않는다.
- 응답 전에 저장 도구 결과와 경고를 확인한다. 새 페이지는 실제 속성·본문을 다시 읽어 확인한다. 기록 실패 시 일반 작업은 계속하고 미저장 범위와 원인을 정확히 알린다.

### 요약

- 사용자의 “오늘 요약”, “오늘 한 일 정리”, 작업 기록 의미의 “요약해”는 한국 날짜의 오늘을 대상으로 한다. 특정 문서 요약 요청과 혼동하지 않는다.
- 기록 홈의 모든 프로젝트 DB를 조회한다. 날짜 범위가 대상 날짜를 포함하거나 날짜 속성이 비어 있는 후보를 페이지네이션 끝까지 읽고 본문의 실제 날짜 섹션을 확인한다. 일부만 읽었으면 전체 요약이라고 하지 않는다.
- 각 세션의 대상 날짜 최하단 `### 오늘 한 일`과 전체 요약 페이지의 같은 날짜 섹션을 갱신한다. 전체 페이지에는 프로젝트별 핵심 기록과 원본 세션 링크를 넣고 최하단에 실제 수행한 일을 요약한다. 미완료는 별도로 구분한다.
- 같은 날짜를 중복 생성하지 않고 재요청 시 기존 내용을 갱신한다. 기록 없는 날은 빈 요약을 만들지 않는다. 다른 채팅 전문에서 누락 기록을 채우지 않는다.
- 자동화 실행 자체는 업무로 재기록하지 않는다. 이 컴퓨터에서 일일 요약 예약을 중복 생성하지 않는다.

## 사용상 한계

프로젝트 생성 즉시 이벤트나 무조건 실행되는 세션 훅을 설치하는 방식이 아니다. 사용자 수준 지침에 따라 첫 요청에서 처리한다. Notion 인증이 필요한 단계는 사용자에게 맡기며 비밀을 읽어 우회하지 않는다. 이 파일로 현재 컴퓨터에서 설정된 사실과 실제 새 세션에서 검증된 사실을 구분한다.
