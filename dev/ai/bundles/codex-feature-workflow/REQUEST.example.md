# 메인 대화에 붙여 넣을 실행 요청 예시

아래 요청에서 대괄호 항목을 실제 내용으로 바꾼다. 이 파일을 저장하는 것만으로 작업이 실행되지는 않는다.

```text
이번 기능 개발은 .codex/workflows/feature-development.md에 따라
designer → implementer → reviewer → tester의 별도 subagent로 순차 진행해.
각 역할의 TOML에 지정된 모델과 지시사항을 적용해.

작업 목표:
[사용자 관점의 결과]

사용자와 이미 합의한 설계:
[확정된 책임, 모델, 인터페이스, 처리 방식과 결정 근거]
[변경하거나 다시 결정하면 안 되는 내용]

설계 원천:
[문서 경로 또는 현재 대화의 합의 내용. 다른 대화라면 요약이나 원문을 제공]

완료 기준:
[확인 가능한 동작과 필요한 테스트]

미정인 업무 결정:
[있으면 기재. 없으면 없음]

허용 변경 범위:
[저장소·기능·파일 범위]

designer는 사용자와의 합의를 숙지하고 설계 일관성을 책임져.
설계를 처음부터 새로 만들거나 기존 합의를 임의로 바꾸지 마.
작업 가능한 범위에서 계속 진행하되, 업무 결정이 필요하면 질문해.
기존 사용자 변경을 보존하고, 요청하지 않은 stage·commit·push는 하지 마.
마지막에는 구현 결과, 검토·리팩토링, 실행한 검증과 미검증 범위를 알려줘.
```
