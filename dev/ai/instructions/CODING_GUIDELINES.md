# 코딩 지침

사용자: yeongju · 갱신일: 2026-10-26

이 파일은 코딩 작업의 공통 지침이다. 작업을 시작할 때 읽고, 현재 작업에서 사용자가 명시한 요구를 우선한다.

## 답변의 근거 구분

- 사용자의 질문에 답할 때, 사용자가 제공한 문서에 직접 명시된 사실은 `문서 근거`, 모델의 해석·추론·판단·제안·설명용 예시는 `해석·제안`으로 명시적으로 구분한다. 두 종류의 내용을 하나의 사실처럼 섞어 설명하지 않는다.
- `문서 근거`에는 해당 문서명과 절·항목 또는 파일 위치를 함께 제시한다. 문서에서 추론한 구현 방식이나 가능한 관계를 문서가 확정한 요구사항·필수 규칙처럼 표현하지 않는다.
- 문서에 없는 내용은 `문서에 명시 없음`, 확인하지 못한 내용은 `확인하지 못함`이라고 밝힌다. 코드나 다른 자료에서 확인한 사실은 그 출처를 별도로 표시하여 사용자 제공 문서의 사실과 구분한다.

## 검증의 책임

- validation은 정확성·소유권·데이터 일관성을 지키는 데 꼭 필요한 것만 수행한다.
- 외부 입력이나 상태가 바뀌는 경계에서 검증하고, 그 호출 경로에서 이미 증명된 조건은 내부 메서드마다 다시 검사하지 않는다.
- 검증을 제거하기 전에 어떤 진입점이 무엇을 보장하는지 호출부를 확인한다. 다른 진입점이 있다면 동일한 보장이 성립하는지도 확인한다.
- 검증 결과·조회값·생성 결과를 같은 작업 범위에서 재사용한다. 같은 owner 전체를 반복 렌더링하거나 검증하지 않는다.
- 여러 줄의 입력 검증이 본문 흐름을 가리면 이름이 분명한 작은 메서드로 분리하거나 검증할 객체 클래스 내부에서 처리한다. 검증용 계층이나 모델을 새로 만들 필요는 없다.
- 문자열의 유사 의미를 임의로 추론하지 않는다. 동일 입력의 재시도와 의도적인 값 변경을 구분하고, 비교 목적을 주석으로 설명한다.

## 확인과 보고

- 의미 있는 동작 변경에는 관련 테스트만 수행한다. 주석 수정만으로 광범위한 테스트를 추가하지 않는다.
- 변경 내용, 실제 통과한 검증, 미검증 범위는 응답으로 보고한다. 사용자 요청 없이 stage·commit하지 않는다.
- 사용자가 요구하지 않은 문서는 생성하거나 남기지 않는다. 변경사항을 docs, 릴리스 노트 등의 파일로 기록하지 않으며, 문서 작성은 명시적으로 요청받은 경우에만 수행한다.

## 프로젝트 구조
- vizend vista라는 코드 생성기가 존재하기 때문에 vista 로 자동생성되는 부분(generated by vista 라는 주석이 적힌 파일들)은 수정하지 않도록 한다.
- facade 모듈의 경우 수정이 가능하지만, url, 명명규칙 등 전체 구조를 그대로 따르고 generated by vista 라는 주석까지 동일하게 작성하도록 한다.
- facade 는 항상 flow/seek 만 호출하도록 하고, flow facade 는 flow만, seek facade 는 seek 만 호출한다.
- feature 의 계층 구조는 flow/seek - action - logic 순이 되고, 같은 계층끼리는 호출할 수 없고 항상 하위 계층을 호출해야 한다. 예를 들어 flow/seek 은 같은 flow/seek 을 호출할 수 없고 action 과 logic만 호출 가능하다.
- 기존재하는 잘못된 호출 구조는 사용자의 요청 시에만 변경한다.
- 기능 생성 시마다 컴포넌트르르 생성하지 않고, 기존재하는 컴포넌트 재사용을 우선한다. 예를 들어 새 기능 생성 시마다 flow/seek 을 생성하지 않고, 같은 feature 로 묶을 수 있는 것은 기존재하는 feature 를 사용하도록 한다.
